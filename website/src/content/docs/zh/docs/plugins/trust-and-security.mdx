## 信任模型

| 类型 | 触发信任 |
| --- | --- |
| 项目本地插件（`.coden/plugins/*.ts`、`--plugin` 目录） | 首次加载时人工确认工作区 |
| 项目 npm 插件 | `plugin install`/`plugin sync` 确认后记录；启动时未信任则跳过并提示 |
| 用户级本地插件 | 无确认（当前用户主动安装） |
| 全局 npm 插件 | 无启动确认（用户主动安装） |

确认只接受 `y`（`--yes` 只影响插件命令，不影响工作区信任）。信任记录保存工作区**真实路径**（`trusted-workspaces.json`，`0600`），符号链接别名不会绕过。

## 权限边界

- **插件不是沙箱**：在 CodeN 主进程内执行，拥有完整用户进程权限，可访问文件、网络、环境变量与子进程。
- 工具 `risk` 只影响调用确认，不提供进程隔离。
- 安装校验导入插件入口：即使禁用生命周期脚本，顶层代码与静态依赖也会以当前用户权限运行。
- 本地 `.ts` 插件通过 `data:` URL 加载，无法被 Node 运行时加载（见 [运行时能力矩阵](../getting-started/requirements)）。

## 生命周期脚本

| 选项 | 行为 |
| --- | --- |
| 默认 | `--ignore-scripts`，生命周期脚本不运行 |
| `--allow-scripts` | 当前包与传递依赖以用户权限运行 `preinstall`/`install`/`postinstall`；先警告并再次确认 |

## 路径与校验

- npm 入口解析后必须位于包目录内，且是安全解析的真实路径（`withinBoundary` + `safeRealpath`）。
- 本地插件目录的信任基于真实路径；目录/文件需通过真实性校验。
- 工具 schema 编译失败、工具重名、导出非法都会跳过该插件，不影响其他插件与内置工具。

## 集成建议

1. 只安装可信来源的插件；审查发布内容（`npm pack --dry-run`、锁文件 diff）。
2. 默认保持生命周期脚本禁用；确有需要时再显式 `--allow-scripts` 并检查依赖树。
3. 项目插件清单与 `bun.lock` 提交版本控制，`node_modules` 不提交。
4. 敏感仓库先确认工作区内容再信任项目插件/Hook。
5. 不信任的插件不要保留在全局作用域（全局插件不重复确认）。
