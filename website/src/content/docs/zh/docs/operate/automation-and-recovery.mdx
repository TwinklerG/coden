自动化应优先使用 print 模式、明确审批策略和可检查退出状态。恢复则依赖本地会话，而不是重放 shell 进程。CI 中没有交互输入时，任何需要人工确认的路径都应被视为配置错误，而不是等待中的任务。

## 自动化

### 非交互运行

```bash
coden -p --auto --lang en "run the tests and fix the first failure"
```

- `-p/--print`：单轮、纯文本、可管道；stdout 是模型输出与工具摘要。
- `--auto`：跳过工作区内工具确认；错误与警告走 stderr。
- 退出码：`0` 完成；`1` 执行失败；`2` 配置错误（缺 API Key、非法参数、配置 JSON 无效）。
- 无 Key 时立即失败：适合 CI 快速失败。

### CI 示例

```bash
#!/usr/bin/env bash
set -euo pipefail
export CODEN_OPENAI_API_KEY="${OPENAI_API_KEY}"
export CODEN_MODEL="${CODEN_MODEL:-gpt-5-mini}"

coden -p --auto --lang en "run the test suite and fix the first failure"

git diff --exit-code -- . ':!dist'        # ensure no unexpected changes
coden --resume                              # print this workspace's sessions
```

`--max-steps` 控制无人值守的步骤预算；`NO_COLOR=1` 可禁止输出颜色（不影响界面模式）。

### 会话编排

```bash
coden -p --auto "run the test suite" | tee /tmp/run-1.txt
coden -p --auto --resume "$(coden --resume | head -1 | cut -d' ' -f1)" "fix the first failure"
```

- 恢复会话继续同一上下文（系统提示与工具目录会重建）。
- `coden --resume` 列表格式：`<id>  <title>  (<N> messages, YYYY-MM-DD HH:MM)`。
- 任务间共享会话可减少上下文重建；一次任务一个 `-p` 调用。

### 门禁模式

- 用 `Stop` Hook 输出 `{"decision":"block","reason":"…"}` 让模型在测试未通过时继续（受 `maxSteps` 限制）。
- 用 `PreToolUse` 的 `permissionDecision: "deny"` 禁止指定工具（例如 `matcher: "git"`）。
- `--verbose` 输出更多运行信息便于日志审计。

### 限制

- 每次调用都会消耗 Provider 配额；无人值守时先以 `--max-steps` 设限。
- `-p` 必须携带 prompt；无 prompt 会失败。
- 需要人工确认的操作（危险命令、工作区外路径、`--smart-approve` 的不确定项）在 `--auto` 下会失败而不是等待。

## 常见错误

### 启动与配置

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `CODEN_OPENAI_API_KEY is required` | 未设置 Key（默认 Provider） | `export CODEN_OPENAI_API_KEY=...` 或配置 `env` 字段 |
| `CODEN_ANTHROPIC_API_KEY is required` | `--provider anthropic` 但未设置 Key | 导出 `CODEN_ANTHROPIC_API_KEY` |
| `Cannot read config ...` | 配置文件 JSON 无效 | 修复对应作用域的 `config.json` |
| `language must be zh or en` | 配置/`--lang` 非法值 | 使用 `zh`/`en`；检查用户配置 |
| `--tui and --cli are mutually exclusive` | 界面参数冲突 | 只保留一个界面选项 |
| `--smart-approve and --auto are mutually exclusive` | 审批参数冲突 | 二选一 |
| `--allow-outside-workspace requires --auto` | 单独使用该选项 | 与 `--auto` 组合 |
| `print mode requires a prompt` | `-p` 未提供任务 | 添加 prompt 参数 |
| `Anthropic enabled thinking requires maxOutputTokens greater than 1024` | `reservedOutputTokens <= 1024` 且启用思考 | 增大 `reservedOutputTokens` 或降低思考等级 |

### 运行期

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `runtime.step_limit`（`Maximum model steps (20) reached`） | 超过 `maxSteps` | 拆分任务或提高 `--max-steps` |
| `context.exhausted` | 紧急压缩后仍超预算 | 用 `/new` 或新会话，减小单次任务范围 |
| `permission.denied` | 权限被拒 | 换用更安全的操作或人工放行 |
| `permission.outside_workspace_denied` | `--auto` 下访问工作区外 | 确有必要时使用 `--auto --allow-outside-workspace` |
| `tool.timeout` | 工具未在 60 秒内完成（且未协作取消） | 缩短命令/工具逻辑；检查插件协作取消 |
| `edit.no_match` / `edit.multiple_matches` | `oldText` 未找到或不唯一 | 精确复制待替换文本 |

### 插件

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `plugin.specifier_invalid` | specifier 不合法 | 使用 `npm:<package>` 或 `npm:<package>@<version-or-tag>` |
| `plugin.install_busy` | 同作用域事务锁被占用 | 稍后重试（过期锁自动清理） |
| `plugin.lock_missing` | 项目 `sync` 缺 `bun.lock` | 先 `plugin install` 或提交锁文件 |
| `plugin.lock_outdated` | 锁文件与清单不一致 | 更新锁文件并提交 |
| `plugin.manifest_invalid` | `plugins.json` 损坏 | 修复清单；必要时删除并重新安装 |
| `plugin.metadata_missing` / `plugin.entry_invalid` / `plugin.api_unsupported` / `plugin.name_mismatch` | 包不符合作者协议 | 对照[插件作者协议](/coden/zh/docs/extend/plugin-authoring/)修正包 |
| 插件加载失败、工具未注册 | 顶层代码/入口异常；Node 运行时加载 `.ts` 插件失败 | 查看 `coden plugin list`；用 Bun 运行或改用 npm 插件 |
| `plugin restart required` | 运行中 npm 插件元数据变化 | 重启 CodeN |

### Hook

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 配置解析失败：`unsupported hook event`/`invalid matcher`/`timeout` 范围 | Hook 配置非法 | 对照 [匹配规则](/coden/zh/docs/extend/skills-and-hooks/) 与 [执行与超时](/coden/zh/docs/agent/failures-and-control-flow/) |
| `X config exceeds 64 commands` | 单事件 Hook 超限 | 精简 Hook |
| Hook 静默失效 | 非零退出、超时、输出超限、非法 JSON | `--verbose` 查看；检查脚本 stdin/stdout 协议 |

### Skill 与运行时

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Skill 未生效 | 目录名/frontmatter 不一致或文件非法 | `--verbose` 查看 `ignored ...` 原因；重启 |
| 本地 `.ts` 插件在 Node 下不加载 | Node 不支持 `data:text/typescript` | 用 Bun 运行（或使用 npm 插件） |

## 会话存储

### 存储位置

```text
$XDG_DATA_HOME/coden/sessions/<workspace-hash>/
├── <session-id>.jsonl          # session records
└── <session-id>.trace.jsonl    # runtime event trace
```

- 默认 `~/.local/share/coden`；`XDG_DATA_HOME` 可整体迁移。
- 目录 `0700`、文件 `0600`；会话按工作区哈希隔离（同一路径不同进程共享目录）。
- 会话 ID 由 UUID 生成，格式 `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`。

### JSONL 记录

每行一个记录：

```json
{"version":1,"id":"…","timestamp":"2026-08-31T12:00:00.000Z","type":"message","data":{"role":"user","content":"…"}}
```

记录类型与恢复语义见 [会话](/coden/zh/docs/agent/sessions/)。会话文件中禁止修改的部分包括消息结构校验（`isMessage`）、工具调用更新的唯一性校验（`tool.call.updated` 必须恰好匹配一条 assistant tool_calls）。

### 恢复校验

- 逐行解析；无效的非末行记录抛出错误（行号），只有**最后一行不完整**时忽略并警告。
- 尾部未完成工具调用自动补齐：`runtime.interrupted: tool execution did not complete before the previous process exited`。
- 恢复成功后 `#created` 置位，后续消息继续追加到同一文件。

### 备份与清理

| 操作 | 结论 |
| --- | --- |
| 备份 | 复制 `<id>.jsonl` 与 `<id>.trace.jsonl` 即可；保留原权限（`0600`） |
| 删除 | 删除两个文件即清除会话；不存在其他索引 |
| 迁移 | 修改 `XDG_DATA_HOME` 后所有会话/trace/全局插件跟随新目录 |

### 敏感性

会话文件可能包含模型推理内容、`redacted-thinking`、签名、用户输入与代码片段。不要未经审查地提交、分享或分发；保持本地私有权限。
