## 全局安装

使用 Bun 或 npm 安装发布后的 CLI：

```bash
bun add -g @twinklerg/coden
# or
npm install -g @twinklerg/coden
```

## 验证安装

```bash
coden --version   # 0.1.9
coden --help
```

`coden --help` 列出全部选项与子命令，包括 `--tui`、`--cli`、`-p/--print`、`--provider`、`--model`、`--resume`、`--auto`、`--smart-approve`、`--allow-outside-workspace`、`--verbose`、`--max-steps`、`--thinking`、可重复的 `--plugin`、`--lang` 和 `--version`。

## 升级与卸载

```bash
bun update -g @twinklerg/coden
# or
npm install -g @twinklerg/coden@latest

bun remove -g @twinklerg/coden
# or
npm uninstall -g @twinklerg/coden
```

## 发布产物说明

- bin 入口是 `dist/index.js`：minify 后的单文件 Node CLI，运行时需要 Node.js 22+，不需要 Bun。
- npm 包只暴露 `@twinklerg/coden/plugin` 一条子路径，供插件作者在构建时获得类型；主入口 `"."` 未公开，`import "@twinklerg/coden"` 会被拒绝。
- 未设置 Provider API Key 时，启动即失败并退出码 2，属于配置错误而不是运行错误。
- 插件依赖 Bun：本地 TypeScript 插件（`*.ts` 文件）需要 Bun 运行时；npm 插件的安装与同步内部调用 `bun install`。详见 [运行时能力矩阵](/coden/zh/docs/getting-started/requirements/)。

## 从源码运行（开发）

```bash
git clone <repository-url>
cd coden
bun install
just check
just build
just run "your task"
```

仓库开发命令：`just build` 构建 CLI 与插件契约；`just test` 运行离线测试；`just check` 运行 lint、类型检查与完整离线测试；`just publish-dry-run` 预演 npm 发布内容而不上传。
