## 分层概览

| 层 | 机制 |
| --- | --- |
| 人机确认 | 工具授权（`manual`/`smart`）、工作区信任、插件确认 |
| 自动化策略 | 风险等级（`read`/`modify`/`dangerous`）、`--auto` 跳过确认 |
| LLM 审查 | Smart Approval 独立审查普通修改（失败关闭） |
| Hook 控制 | `PreToolUse`/`PermissionRequest`/`Stop` 决策（`deny > ask > allow`） |
| 路径约束 | 结构化文件工具按真实路径分类 + TOCTOU 复验 |
| 输出约束 | 有界输出、控制字符清洗、密钥脱敏、提示词注入边界 |
| 数据约束 | `0700`/`0600` 会话与 trace；不自动上传 |

## 信任清单

- 项目插件（本地 `.ts` 与 npm）与项目 Hook 需要**工作区信任**：按真实路径显式确认一次（`trusted-workspaces.json`）。
- 用户级插件/Hook 视为用户主动安装，不重复确认。
- `--auto` 不跳过信任；`--yes` 只影响插件命令。
- 所有信任判定使用真实路径，符号链接别名不绕过。

## 权限模型

| 权限 | 默认 | `--smart-approve` | `--auto` |
| --- | --- | --- | --- |
| `read` | 允许 | 允许 | 允许 |
| `modify`（工作区内） | 人工 | LLM 审查 → 不确定人工 | 允许 |
| `dangerous` | 人工（无会话授权） | 人工 | 允许（Hook `deny` 生效） |
| 工作区外 `read`/`write`/`edit` | 按修改处理（人工） | 人工 | 拒绝（除非 `--allow-outside-workspace`） |

## 非沙箱声明

- `bash`、插件与 Hook 以**当前用户进程权限**运行：可访问文件、网络、环境变量与子进程。
- 风险等级只影响确认流程，不提供进程隔离。
- npm 插件安装校验会导入入口：顶层代码以当前用户权限执行（生命周期脚本默认禁用）。
- 插件依赖 Bun：本地 `.ts` 插件在 Node 运行时无法加载（不构成安全边界）。

## 数据边界

- 会话与 trace：本地 `0700`/`0600`；可能包含推理内容、签名与输入；不自动上传。
- Provider 调用：消息、工具定义与工具结果发送到所配置的 Provider（端点由 `CODEN_OPENAI_BASE_URL` 决定）。
- 错误脱敏：环境变量值（≥8 字符）替换为 `[redacted]`；Hook 输出清洗控制字符。

## 已知限制

1. 没有独立沙箱；不隔离网络访问。
2. 危险命令识别是正则启发式，可被绕过（护栏而非安全边界）。
3. LLM 审批不是沙箱，且依赖审查模型的判断。
4. 插件作者可以声明任意 `risk`；`dangerous` 声明只影响确认。
5. `--allow-outside-workspace` 允许修改工作区之外任意路径，仅在明确需要时使用。

## 威胁模型要点

- **供应链**：插件/Hook 属于受信代码执行；信任确认是唯一门槛 → 安装前审查包与脚本。
- **提示注入**：文件内容作为上下文进入模型；系统提示明确普通项目内容不能提升为指令；Hook payload 标记不可信。
- **本地攻击者**：会话文件包含敏感内容，权限 `0600`；共享机器/备份时注意。
- **误操作**：危险命令识别、输入预览（授权时显示）、`edit` 唯一性校验都是防误操作的护栏。
