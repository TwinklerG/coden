插件协议参考描述机器可校验的边界，而不是生态承诺。只有公开导出子路径、manifest 字段、工具类型、Schema 规则和当前加载错误属于这里；包管理来源、热重载和运行时能力必须按当前版本限制理解。

## 本地 TypeScript 插件

### 扫描位置

| 来源 | 路径 | 信任 |
| --- | --- | --- |
| 用户级 | `~/.config/coden/plugins/*.ts` | 无需（视为用户主动安装） |
| 项目级 | `<workspace>/.coden/plugins/*.ts` | 需要工作区信任 |
| 附加目录 | `--plugin <path>` 或配置 `plugins` 条目（可重复） | 项目语义：需要工作区信任 |

目录内 `.ts` 文件按文件名排序加载。项目级目录不存在时静默跳过。

### 单文件约束

- 插件必须是**自包含单文件**：通过 `data:text/typescript` URL 在进程内导入，相对路径导入（`./helper.ts`）无法解析；npm 包导入（`import pc from "picocolors"`）正常。
- 内容哈希用于模块缓存：内容未变的插件 `/reload` 复用已加载模块；变更后重建模块并原子替换工具注册表。
- 顶层代码会在加载时执行——这与授权无关，属于信任边界的一部分。

### 最小示例

```ts
import type { ToolDefinition } from "@twinklerg/coden/plugin";

const tool: ToolDefinition = {
  name: "line_count",
  description: "Count lines in supplied text",
  risk: "read",
  inputSchema: {
    type: "object",
    additionalProperties: false,
    required: ["text"],
    properties: { text: { type: "string" } },
  },
  async execute(input) {
    const { text } = input as { text: string };
    return { content: String(text.split("\n").length) };
  },
};

export default tool;
```

### 加载与校验

- 导出可以是单个 `ToolDefinition` 或 `CodeNPlugin`（`apiVersion: 1`、`name`、非空 `tools` 数组）。
- 工具名须匹配 `^[a-zA-Z][a-zA-Z0-9_-]{0,63}$`；输入 schema 用 Ajv 编译校验；`execute` 返回 `{ content, isError?, metadata? }`。
- 重名（含与内置工具冲突）时**整个插件跳过**，不覆盖既有工具，不阻止其他插件。
- 执行上下文：`ToolContext` 提供 `workspace`、`signal`（`AbortSignal`，60 秒超时需协作取消）与结构化文件路径信息。

### 运行时要求

本地 `.ts` 插件由 Bun 加载。**Node.js 运行时下无法加载**：Node 对 `data:text/typescript` 返回 `ERR_UNKNOWN_MODULE_FORMAT`，该插件被跳过并记为失败（不影响其他功能）。从源码用 Bun 运行或确保 PATH 上存在 Bun 才能使用本地 TypeScript 插件。

## npm 插件安装和管理

### 安装

```bash
coden plugin install npm:@scope/coden-plugin-example
coden plugin install npm:@scope/coden-plugin-example@^2 --global
coden plugin remove @scope/coden-plugin-example
coden plugin list
coden plugin sync
```

- 默认安装到**项目级**；`--global` 安装到当前用户全局。
- specifier 仅接受 `npm:<package>` 或 `npm:<package>@<version-or-tag>`；固定使用 `https://registry.npmjs.org`，不支持私有 Registry、Git、URL 或本地目录源。
- 安装会执行校验导入：入口被真实导入，顶层代码以当前用户权限运行。
- 安装/删除/升级后必须重启 CodeN 生效；`/reload` 只重读本地 `.ts` 插件。

### 项目文件

```text
<workspace>/.coden/plugins.json              # manifest (commit)
<workspace>/.coden/plugin-runtime/.gitignore # excludes node_modules (commit)
<workspace>/.coden/plugin-runtime/bun.lock   # locked dependencies (commit)
```

`plugin-runtime/package.json` 由 `plugins.json` 确定性生成，`node_modules/` 不提交。全局插件位于 `$XDG_DATA_HOME/coden/plugins/`（默认 `~/.local/share/coden/plugins/`），不属于项目仓库。

### 同步

```bash
coden plugin sync
coden plugin sync --global
```

- 项目级 `sync` 要求 `plugin-runtime/bun.lock` 存在，否则报 `plugin.lock_missing`。
- 同步以 `--frozen-lockfile` 运行 `bun install`：锁文件过期报 `plugin.lock_outdated`，需更新并提交锁文件。
- 同步会重建运行时并重新校验全部插件入口。

### 生命周期脚本

| 行为 | 说明 |
| --- | --- |
| 默认禁用 | 等价于 `bun install --ignore-scripts`；`preinstall`/`install`/`postinstall` 不运行 |
| `--allow-scripts` | 允许当前包与传递依赖以用户权限运行脚本；会先输出警告并再次确认 |
| `--yes` | 只跳过确认提示，**不会**自动启用脚本 |

### 列表与遮蔽

`coden plugin list` 输出项目与全局两组：包名、安装版本、请求版本、工具数。同一包名同时存在于两级时，项目版本显示为已遮蔽（`shadowed by project`），全局版本不生效。

### 事务与并发

- 安装/同步/删除以事务方式提交（manifest + runtime 备份、崩溃后自动恢复）。
- 同一作用域一次只能有一个事务；并发操作报 `plugin.install_busy`（残留的过期锁会自动清理）。

### 运行时要求

npm 插件的**加载**只要求入口是构建后的 `.js`/`.mjs`（Node 或 Bun 都可）；**安装与同步**内部调用 `bun install`，需要 PATH 上有 Bun。

## 插件作者协议

### package.json 要求

```json
{
  "name": "@scope/coden-plugin-example",
  "version": "1.0.0",
  "type": "module",
  "files": ["dist"],
  "coden": {
    "apiVersion": 1,
    "plugin": "./dist/index.js"
  }
}
```

| 字段 | 要求 |
| --- | --- |
| `type` | 必须是 `"module"` |
| `coden.apiVersion` | 必须是 `1` |
| `coden.plugin` | 以 `./` 开头的 `.js` 或 `.mjs` 路径；不得含 `..`、`\`、`://` 或空白 |
| 入口文件 | 必须发布**构建后**的 JS；只发布 TypeScript 源码会被拒绝 |
| 入口边界 | 解析后的真实路径必须位于包目录内 |

### 导出形态（二选一）

单工具：默认导出 `ToolDefinition`：

```ts
import type { ToolDefinition } from "@twinklerg/coden/plugin";

const tool: ToolDefinition = {
  name: "example_echo",
  description: "Echo supplied text",
  risk: "read",
  inputSchema: {
    type: "object",
    additionalProperties: false,
    required: ["text"],
    properties: { text: { type: "string" } },
  },
  async execute(input) {
    const { text } = input as { text: string };
    return { content: text };
  },
};

export default tool;
```

多工具：默认导出 `CodeNPlugin`，其中 `name` 必须等于 npm 包名：

```ts
import type { CodeNPlugin, ToolDefinition } from "@twinklerg/coden/plugin";

const readTool: ToolDefinition = {
  name: "example_read",
  description: "Read example data",
  risk: "read",
  inputSchema: { type: "object", additionalProperties: false },
  async execute() {
    return { content: "read" };
  },
};

const plugin: CodeNPlugin = {
  apiVersion: 1,
  name: "@scope/coden-plugin-example",
  tools: [readTool],
};

export default plugin;
```

### 校验规则

| 检查 | 失败时的错误 |
| --- | --- |
| 导出不是工具或插件对象 | `plugin.export_invalid` |
| `apiVersion` 不是 1 | `plugin.api_unsupported` |
| `CodeNPlugin.name` 与包名不一致 | `plugin.name_mismatch` |
| `tools` 为空或含非法工具 | `plugin.export_invalid` |
| 工具名不匹配 `^[a-zA-Z][a-zA-Z0-9_-]{0,63}$` | `tool.invalid_name` |
| 与已有工具重名 | `tool.duplicate`（本地加载）/ `plugin.tool_conflict`（npm 组合） |
| inputSchema 非法 | `tool.invalid_schema` |

### 公共契约

- `@twinklerg/coden/plugin` 是唯一公开子路径；主入口 `"."` 未公开，`import "@twinklerg/coden"` 会被拒绝。
- `ToolDefinition`/`CodeNPlugin` 类型从该子路径导入；把 `@twinklerg/coden` 放入 `devDependencies`，`import type` 在构建时移除，运行时不会加载另一份 CodeN。
- `ToolContext.signal` 是 `AbortSignal`：tsconfig 需提供相应 lib（如 `@types/node` 或 DOM）。
- 契约以仓库 `src/plugin/index.ts` 为唯一来源；构建自动生成 `dist/plugin/index.js` 与 `dist/plugin/index.d.ts`，不发布 `src`。
