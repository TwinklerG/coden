## CodeN 是什么？

一个用 TypeScript 独立实现的极简编程智能体：直接使用模型原生 Tool Calling，在本地读取、修改文件和执行命令，不依赖 Agent 框架或服务端代码执行。

## 需要 Node 还是 Bun？

| 场景 | 要求 |
| --- | --- |
| 运行发布版 CLI | Node.js 22+ |
| 本地 TypeScript 插件（`*.ts`） | Bun（Node 下无法加载） |
| npm 插件安装/同步 | PATH 上需要 `bun` |
| 从源码开发 | Bun 1.1+ 与 Just |

## 支持哪些模型？

`openai` 与 `anthropic` 两个 Provider，模型 ID 由用户显式指定（默认 `gpt-5-mini`）。CodeN 不维护模型能力白名单，参数按原样发送。详见 [配置第一个 Provider](/coden/zh/docs/getting-started/provider/)。

## 支持自定义端点吗？

OpenAI 兼容端点：`CODEN_OPENAI_BASE_URL`。Anthropic 固定使用官方端点。详见 [自定义 Base URL](/coden/zh/docs/advanced/custom-base-url/)。

## 会话保存在哪里？

`$XDG_DATA_HOME/coden/sessions/<workspace-hash>/`（默认 `~/.local/share/coden`）。文件权限 `0700`/`0600`；内容含模型输出与推理，属敏感数据。详见 [会话存储](/coden/zh/docs/advanced/session-storage/)。

## 如何控制用量？

- `-p --auto` 单轮执行，CI 友好。
- `--max-steps` 限制步骤数（默认 20）。
- `--resume <id>` 恢复上下文，避免重复建立上下文。
- 思考等级影响输出预算分配（Anthropic 预算计入 `reservedOutputTokens`）。

## 插件会做危险的事吗？

插件与 `bash` 一样以当前用户进程权限运行，**不是沙箱**。防护措施：项目插件需要工作区信任；npm 生命周期脚本默认禁用；危险命令识别；`--auto` 不跳过信任确认。详见 [插件信任与安全](/coden/zh/docs/plugins/trust-and-security/)。

## 支持私有 npm Registry 吗？

不支持。npm 插件固定使用 `https://registry.npmjs.org`，specifier 仅接受 `npm:<package>[@version]` 形式；私有 Registry、Git、URL 与本地目录源均不受支持。

## 如何恢复一个被中断的任务？

重启后 `coden --resume <session-id>`；中断的工具调用会以 `runtime.interrupted` 错误补齐，模型可继续。

## 如何参与开发？

```bash
git clone <repository-url>
cd coden
bun install
just check
```

`just build` 构建 CLI 与插件契约；`just publish-dry-run` 预览 npm 发布内容。

## 文档里的命令都验证过吗？

是的。每条命令、默认值与行为都以当前源码、测试与实际构建产物为准；无法验证的内容不在文档中出现。
