## 覆盖顺序（从高到低）

| 层级 | 来源 |
| --- | --- |
| 1 | CLI 参数（`--provider`、`--model`、`--max-steps`、`--thinking`、`--lang`、`--plugin`） |
| 2 | `CODEN_*` 环境变量（`CODEN_PROVIDER`、`CODEN_MODEL`、`CODEN_MAX_STEPS`、`CODEN_THINKING_LEVEL`） |
| 3 | `<workspace>/.coden/config.json`（项目级） |
| 4 | `~/.config/coden/config.json`（用户级；`XDG_CONFIG_HOME` 可覆盖） |
| 5 | 内置默认值 |

## 特例与合并规则

| 字段 | 规则 |
| --- | --- |
| `language` | 用户专属偏好：只从用户级配置读取，项目级同名字段被**忽略**；`--lang` 优先级最高但仅影响当前进程；`/lang` 原子写回用户配置 |
| `plugins` | **拼接**而非覆盖：用户级 → 项目级 → CLI `--plugin`，按此顺序生效 |
| `env` | 两级合并后**逐键注入**进程环境；项目级逐键覆盖用户级；**不覆盖** shell 中已导出的同名变量（shell 导出 > 配置 env） |
| `hooks` | 合并为有序列表：用户级 Hook 在前、项目级 Hook 在后；同一事件最多 64 条 |

其余字段（`provider`、`model`、`approvalModel`、`approvalStrictness`、`maxSteps`、`contextWindow`、`reservedOutputTokens`、`safetyMargin`、`thinkingLevel`）为简单覆盖：高优先级层的值完全替换低优先级层。

## 配置读取时机

- 配置只在进程启动时读取一次；修改后需重启（`/reload` 只重新加载插件，不重读配置）。
- 任一层 JSON 无效（语法、类型、非法值）都会导致启动失败：`Cannot read config ...`，退出码 2。
- 会话列表（`coden --resume` 不带 ID）也会加载配置并执行上述校验。

## 环境变量错误

`CODEN_PROVIDER`、`CODEN_MODEL`、`CODEN_MAX_STEPS`、`CODEN_THINKING_LEVEL` 的非法值在加载时抛错，不会静默降级。
