CodeN is a hackable coding agent built around pluggable tool plugins. Its core execution path stays small and inspectable: the model sees tool contracts and decides when to call them; CodeN validates, authorizes, executes, records, and returns results to the next model request. “Hackable” means that you can observe and reshape this path, not that the product relies on a marketing persona.

These docs are for readers who want to understand an agent rather than merely copy commands. Build a model of the runtime and its security boundaries first, then choose Plugins, Skills, Hooks, or project instructions to extend it; use the protocol reference for exact fields. Every behavioral claim is grounded in the current source, tests, and published artifact.

CodeN (Code NJU) is a hackable coding agent built around pluggable tool plugins. It drives provider-native tool calling to read, modify, and execute commands locally; its small, inspectable core does not depend on an agent framework or server-side code execution.

## Shortest path to a first task

```bash
bun add -g @twinklerg/coden      # or npm install -g @twinklerg/coden
export CODEN_OPENAI_API_KEY=...  # or CODEN_ANTHROPIC_API_KEY
coden "fix the failing tests in this project"
```

Install, configure, and finish a first task in three commands. CodeN starts in the CLI/REPL by default and treats the working directory as its workspace.

## Boundaries to keep in mind

- Every command, configuration key, and behavior in these docs is verified against the current source code.
- CodeN does not read the system locale; the default interface language is Chinese.
- `bash` and plugins run with the current user's process permissions. This is not a general-purpose sandbox; risk classification is a heuristic guard against mistakes.
- Session JSONL and trace files may contain sensitive content; do not share them without review.
