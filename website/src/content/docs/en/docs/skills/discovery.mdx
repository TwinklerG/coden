## Scan locations (once at startup)

```text
~/.agents/skills/<skill-name>/SKILL.md     # user
<workspace>/skills/<skill-name>/SKILL.md   # project (bundled)
<workspace>/.agents/skills/<skill-name>/SKILL.md  # project (local)
```

Direct subdirectories are scanned in that order; each candidate must be `<skill-name>/SKILL.md`.

## Override order

Same-named skills override in user → bundled → local order, so locally installed project skills win. `skills/` is for repository-bundled, publicly distributable skills; `.agents/skills/` is for locally installed project skills.

## Format validation

| Rule | Requirement |
| --- | --- |
| frontmatter | must start with a parseable YAML frontmatter block |
| `name` | `^[a-z0-9][a-z0-9-]{0,63}$` and must match the directory name |
| `description` | non-empty string, ≤ 1024 characters |
| size | `SKILL.md` ≤ 1MB |
| paths | no symlink escape from the scan root; must be a regular file |

Optional frontmatter fields: `license`, `compatibility`, `metadata`, `allowed-tools`.

Invalid entries are skipped; `--verbose` prints each failure reason (scope, path, reason). A failure affects neither other skills nor startup.

## Context injection

- The startup context (system prompt) contains only each active skill's **name and description** (`formatSkillCatalog`).
- When a task matches, the model calls `activate_skill` to load the full instructions and the skill's absolute root; resources such as `references/` and `scripts/` are read with ordinary tools as needed.
- With no active skill, `activate_skill` returns `skill.not_found`.
- Skills are discovered at startup only: file changes require a CodeN restart.
