## Launch and fallback

```bash
coden --tui "your task"
coden --tui
```

`--tui` requires stdin and stdout to both be TTYs, raw mode to be available, and `TERM != dumb`. If any condition fails it falls back to the CLI with a warning (not an error); TUI initialization failures fall back the same way. `--tui` cannot be combined with `--cli` or `--print`.

## Layout

- The content area keeps the CLI style: transient thinking and tool activity enter the transcript stream at the current conversation position.
- The input area is enclosed by two full-width horizontal rules; below it the status row shows provider/model, workspace, authorization mode, phase, and context occupancy.
- While an interaction is pending (authorization, trust, plugin confirmation) the input area stays visible but disabled, and the request renders inline in the transcript instead of a dialog.
- Requests, available choices, and the final selection remain permanently in the current transcript.

## Keybindings

| Key | Behavior |
| --- | --- |
| `Enter` | submit input |
| `Shift+Enter` / trailing `\` | insert a newline |
| `Ctrl+P` / `Ctrl+N` | browse input history |
| `PageUp` / `PageDown`, mouse wheel | scroll the transcript |
| `End` | return to the latest content |
| `Ctrl+C` while running | cancel the current task |
| `Ctrl+C` while idle | begin the exit flow (after confirmation) |
| `Ctrl+D` with empty input | exit |
| `Esc` | deny the pending inline authorization request |

## Execution model

- Single-task serial execution: input is not queued while running, and the input area stays disabled until completion or cancellation.
- The same slash-command set is available (`/help`, `/skills`, `/session`, `/sessions`, `/compact`, `/reload`, `/new`, `/lang`, `/thinking`, `/quit`).
- Escape sequences are disambiguated via the Kitty keyboard protocol; `Ctrl+C` does not terminate the process directly (handled in-process).
