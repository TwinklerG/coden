## Command list

| Command | Behavior |
| --- | --- |
| `/help` | lists all commands |
| `/skills` | lists active skills (name, description, project/user scope) without calling the model |
| `/session` | prints the current session ID |
| `/sessions` | lists all sessions of the current workspace (newest activity first) |
| `/compact` | compacts context immediately (runs the automatic flow; result is persisted) |
| `/reload` | reloads local TypeScript plugins and the npm plugin registry; prints loaded/failed/tool summary |
| `/new` | starts a new conversation in the current session (keeps system messages; clears summary and history) |
| `/lang` | lists `zh`, `en`, and the current language |
| `/lang <zh\|en>` | switches language; atomically writes the user config with mode `0600` and takes effect immediately |
| `/thinking` | lists thinking levels, the current value, and the effective mapping |
| `/thinking <level>` | switches level and persists it to the current session |
| `/quit` | exits |

## Parsing rules

- A command must occupy a single line: input containing newlines (such as `multiline input\n/help`) is treated as a message.
- Command names match exactly: leading/trailing whitespace of `/help` is trimmed before recognition; unknown prefixes submit as a normal task.
- Invalid arguments never end the session: `/lang xx` and `/thinking xx` print the error plus the available list and continue.

## Side-effect notes

- `/lang` accepts only `zh`/`en`; it writes the **user-level** config file, preserving other fields.
- `/thinking` affects only the current process and session, never user/project config files.
- `/reload` guarantees re-reading local `.ts` plugins only; npm package changes require a CodeN restart.
- `/new` does not change the thinking level; the session grant set (`s` grants) is bound to the current process and survives `/new`.
