## package.json requirements

```json
{
  "name": "@scope/coden-plugin-example",
  "version": "1.0.0",
  "type": "module",
  "files": ["dist"],
  "coden": {
    "apiVersion": 1,
    "plugin": "./dist/index.js"
  }
}
```

| Field | Requirement |
| --- | --- |
| `type` | must be `"module"` |
| `coden.apiVersion` | must be `1` |
| `coden.plugin` | a `.js` or `.mjs` path starting with `./`; no `..`, `\`, `://`, or whitespace |
| entry file | must publish **built** JS; publishing TypeScript source only is rejected |
| entry boundary | the resolved real path must stay inside the package directory |

## Export shapes (pick one)

Single tool: default-export a `ToolDefinition`:

```ts
import type { ToolDefinition } from "@twinklerg/coden/plugin";

const tool: ToolDefinition = {
  name: "example_echo",
  description: "Echo supplied text",
  risk: "read",
  inputSchema: {
    type: "object",
    additionalProperties: false,
    required: ["text"],
    properties: { text: { type: "string" } },
  },
  async execute(input) {
    const { text } = input as { text: string };
    return { content: text };
  },
};

export default tool;
```

Multiple tools: default-export a `CodeNPlugin` whose `name` equals the npm package name:

```ts
import type { CodeNPlugin, ToolDefinition } from "@twinklerg/coden/plugin";

const readTool: ToolDefinition = {
  name: "example_read",
  description: "Read example data",
  risk: "read",
  inputSchema: { type: "object", additionalProperties: false },
  async execute() {
    return { content: "read" };
  },
};

const plugin: CodeNPlugin = {
  apiVersion: 1,
  name: "@scope/coden-plugin-example",
  tools: [readTool],
};

export default plugin;
```

## Validation rules

| Check | Error on failure |
| --- | --- |
| export is not a tool or plugin object | `plugin.export_invalid` |
| `apiVersion` is not 1 | `plugin.api_unsupported` |
| `CodeNPlugin.name` differs from the package name | `plugin.name_mismatch` |
| `tools` empty or containing invalid tools | `plugin.export_invalid` |
| tool name not matching `^[a-zA-Z][a-zA-Z0-9_-]{0,63}$` | `tool.invalid_name` |
| name collides with an existing tool | `tool.duplicate` (local load) / `plugin.tool_conflict` (npm composition) |
| invalid inputSchema | `tool.invalid_schema` |

## Public contract

- `@twinklerg/coden/plugin` is the only public subpath; the main entry `"."` is not public and `import "@twinklerg/coden"` is rejected.
- Import `ToolDefinition`/`CodeNPlugin` types from that subpath; put `@twinklerg/coden` in `devDependencies`, and `import type` is erased at build time so no second copy loads at runtime.
- `ToolContext.signal` is an `AbortSignal`: the tsconfig must provide a lib defining it (such as `@types/node` or DOM).
- `src/plugin/index.ts` in the repository is the single source of the contract; the build emits `dist/plugin/index.js` and `dist/plugin/index.d.ts` and never publishes `src`.
