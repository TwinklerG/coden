## Secret management

| Location | Meaning |
| --- | --- |
| shell export (preferred) | `export CODEN_OPENAI_API_KEY=...` before startup; highest precedence |
| user config `env` | `~/.config/coden/config.json`; the project-level file works the same; never overwrites an exported shell variable |
| forbidden | directories that get committed/shared/distributed; CodeN does not read `.env` automatically |

The `env` injection runs before provider creation, so either config scope can carry keys. Project-level `.coden/config.json` is ignored by `.gitignore`, but prefer the user config to avoid keys being copied to teammates.

## Sessions and traces

- Location: `$XDG_DATA_HOME/coden/sessions/<workspace-hash>/`; permissions are `0700` for directories and `0600` for files.
- Content: full message history (including model output), Anthropic extended-thinking `thinking`/`redacted-thinking`/signatures, tool call inputs and results, compaction summaries, and the runtime event trace.
- Sensitivity: these files are sensitive — they may include source fragments, environment context, and reasoning; do not commit, share, or distribute them without review.
- Resume (`--resume`) reads only the local data directory and makes no network calls.

## Permission boundaries

- **Not a general-purpose sandbox**: `bash` and plugins (local/npm) run with the current user's process permissions and can access files, network, environment variables, and subprocesses.
- Built-in structured file tools (`read`/`write`/`edit`) are confined to the workspace by real path (or explicitly widened by `--auto --allow-outside-workspace`).
- Risk levels (`read`/`modify`/`dangerous`) affect only the authorization flow, not process isolation.
- npm plugin installs disable lifecycle scripts by default, but install validation imports the plugin entry — top-level code executes with the current user's permissions.

## Logging and error handling

- Environment variable values in provider error messages are redacted (length ≥ 8 is replaced with `[redacted]`).
- Hook output is scrubbed of terminal control characters (`sanitizeTerminalText`).
- Workspace trust records store the **real path** so symlink aliases cannot bypass confirmation.

## Minimal-exposure recommendations

1. Keep keys in the user config or shell exports only.
2. Before first use of project hooks/plugins, confirm the workspace content is trustworthy.
3. When running unattended with `--auto`, confirm the task scope and the `maxSteps` ceiling first.
4. Avoid `--allow-outside-workspace` in sensitive repositories.
