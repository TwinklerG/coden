## Scope comparison

| Scope | Path | Ownership |
| --- | --- | --- |
| user | `~/.config/coden/config.json` (`$XDG_CONFIG_HOME/coden/config.json`) | the current user; shared across projects |
| project | `<workspace>/.coden/config.json` | a single project; ignored by `.gitignore` and not committed by default |

The data directory is separate from config: `$XDG_DATA_HOME/coden/` (default `~/.local/share/coden/`) holds sessions and global plugins and is not part of the project repository.

## Project file layout

```text
.coden/
├── config.json          # project config (gitignored)
├── plugins.json         # npm plugin manifest (recommended to commit)
├── plugin-runtime/      # plugin runtime; package.json generated from the manifest, node_modules not committed
└── plugins/*.ts         # local TypeScript plugins (gitignored)
```

## Merge behavior

| Behavior | Meaning |
| --- | --- |
| project overrides user | except `language` (user-owned), the project-level field replaces the same-named field |
| `plugins` concatenated | user + project + CLI, applied in that order |
| `env` merged | project keys override user keys; shell-exported variables are not overwritten |
| `hooks` merged | user hooks first, project hooks after, numbered consecutively |

## Project config example

```json
{
  "provider": "anthropic",
  "model": "claude-sonnet-4-20250514",
  "maxSteps": 40,
  "thinkingLevel": "medium"
}
```

## Trust differences

- Project hooks and project npm plugins require **explicit workspace trust** on first use (the real path is recorded in `~/.config/coden/trusted-workspaces.json`).
- User hooks and global plugins are treated as user-initiated installs and are not re-confirmed at every startup.
- `--auto` never skips project-level trust.
